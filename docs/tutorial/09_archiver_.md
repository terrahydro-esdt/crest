# Chapter 9: Archiver

Welcome back to the `crest` tutorial! In the [previous chapter](08_digital_replica_engine_.md), we explored the **Digital Replica Engine**, the high-level control panel that orchestrates a complete `crest` workflow, bringing together configuration, data handling, and the model to run tasks like nowcasting.

Running a task with the `DigitalReplicaEngine` or directly with a `Model` produces results – often large arrays of predictions over space and time. But where do these results go? How do you collect, organize, and save potentially millions or billions of predicted values?

Imagine you've finished a big data analysis project or trained a complex machine learning model that makes predictions across a wide area. You have all these numbers representing your results, but they are just sitting in memory or produced batch by batch. You need a system to:

1.  Collect the predictions from different locations and times as they are produced.
2.  Handle situations where the *same* location might have been predicted multiple times (this happens in `crest` when using sample windows that overlap between data blocks). You don't want to just overwrite; you might want to average the predictions for that location.
3.  Store the final, organized results neatly on disk in a standard file format (like Zarr or NetCDF) that other tools can easily read.

This is where the **Archiver** component comes in.

## What is the Archiver in CREST? (The Filing Cabinet Analogy)

The `crest.Archiver` class is like your **specialized filing cabinet and librarian** for model predictions. Its job is to take the raw results generated by your model, put them in the right "place" (on your output grid), combine them intelligently if needed, and save them nicely organized in durable files.

Specifically, the `Archiver` is responsible for:

1.  **Collecting Predictions:** Receiving batches of predictions along with their corresponding coordinates (like latitude, longitude, time).
2.  **Aggregating Overlaps:** Handling predictions for the same output grid cell that come from different input samples. It doesn't just save the last prediction; it keeps track of all predictions for a cell and can compute statistics, most commonly the *average*.
3.  **Structuring Output:** Inserting the collected and aggregated predictions onto a defined output grid.
4.  **Saving to Disk:** Writing the final results to a file in a standard format like Zarr or NetCDF.

The `Archiver` works closely with the output of your prediction process (typically batches produced by a [Batcher](04_batching_.md) as orchestrated by a [Model](05_model_.md) or [Digital Replica Engine](08_digital_replica_engine_.md)).

## Your Use Case: Saving Soil Moisture Predictions

Let's return to our use case: predicting soil moisture using satellite and weather data. Our [Model](05_model_.md), fed by batches from the [Batching](04_batching_.md) component (which uses [Data Abstractions](02_data_abstractions_.md) and [Data Matching](03_data_matching_.md)), outputs predictions for small spatial/temporal windows (samples).

Due to overlapping sample windows (configured in [Data Abstractions](02_data_abstractions_.md)), a single grid cell in our output area might be covered by predictions from multiple overlapping samples. We want the final saved value for that grid cell to be the *average* of all predictions that covered it.

We need the `Archiver` to:

1.  Know the grid we want to save the final results onto (the output schema).
2.  Receive each batch of predictions as they are generated.
3.  For each batch, figure out which output grid cells the predictions map to.
4.  Keep a running total (sum and count) for each output grid cell.
5.  Once all batches are processed, calculate the final average (`sum / count`) for each cell.
6.  Save this final averaged grid to our desired output file (e.g., `soil_moisture_predictions.zarr`).

## Using the Archiver Component

The primary way to use the `Archiver` is to create an instance within a `with` statement and then repeatedly call its `archive()` method with the prediction results from your model. The `with` statement ensures that the `Archiver` correctly finalizes the output file when the prediction process is complete.

You need to tell the `Archiver`:

1.  Where to save the final output file (`output_path`).
2.  What the grid structure of that output file should be (`data_schema`). This tells the archiver the target coordinates (lat, lon, time) where it should place the predictions.

The `data_schema` can be defined in several ways, but a common approach is to base it on one of the original `Datafile`s from your input [Dataset](02_data_abstractions_.md) or by providing coordinate arrays directly.

*   We define the `output_path` where the final results will be saved. It should end in `.zarr` or `.nc`.
*   We create an `Archiver` instance inside a `with` statement.
*   `output_path`: Specifies the destination file.
*   `data_schema`: This tells the `Archiver` the target grid onto which predictions should be mapped. You could also provide a dictionary of coordinate arrays directly. If the `output_path` *already exists*, the `Archiver` will use the grid *from that existing file* as the schema, ignoring `data_schema` and `datafile_index` (unless `overwrite=True`).
*   `overwrite`: If `output_path` exists, set this to `True` to delete the old file and start fresh. Be careful with this!
*   `keep_stats`: The `Archiver` works by calculating intermediate statistics (sum and count) for each output grid cell and saving them to a temporary Zarr file (`output_path_stats`). At the end, it loads these stats, calculates the average, and saves the final result. `keep_stats=False` means the intermediate stats file is removed after the final output is saved. If you plan to *update* an existing archive file later by running more predictions on it, you *must* keep the stats file (`keep_stats=True`).
*   Inside the `with` block is where your prediction loop runs. For *each* batch of predictions you generate, you call `archiver.archive(coord_dict, pred_dict)`.
    *   `coord_dict`: A dictionary containing the coordinate values (NumPy arrays) for *each point/sample* in the current batch. The keys should match the dimensions of your desired output grid (e.g., `'latitude'`, `'longitude'`, `'time'`).
    *   `pred_dict`: A dictionary containing the predicted values (NumPy arrays) for each output feature generated by your model for the current batch. The keys are the feature names (e.g., `'prediction'`).
    *   The shapes of arrays in `coord_dict` and `pred_dict` must align such that for each coordinate value in `coord_dict`, there's a corresponding predicted value in `pred_dict`.
*   When the `with` block finishes (either normally or due to an error), the `archiver.__exit__` method is automatically called, which triggers the `archiver.close()` method. This finalizes the archiving process.

The `per_sample` and `task_bytes` parameters provide control over how the `Archiver` processes batches and manages memory, but for basic use, the default settings are often sufficient. `per_sample=True` can sometimes be more memory efficient for very large samples by processing them individually within the batch. `task_bytes` lets you specify a memory limit for the intermediate statistics before they are written to disk.

## Behind the Scenes: How the Archiver Works

The `Archiver` is designed to efficiently handle potentially large volumes of predictions and the complexity of aggregation.

Here's a simplified flow of what happens:

```{mermaid}
sequenceDiagram
    participant You as Your Code
    participant Archiver as crest.Archiver
    participant OutputSchema as Output Grid Schema (xarray)
    participant TempStatsFile as Intermediate Stats (Zarr)
    participant FinalOutputFile as Final Output (Zarr/NetCDF)

    You->>Archiver: Create Archiver(output_path, data_schema, ...) in 'with' block
    Archiver->>OutputSchema: Determine/Load output grid structure (`_create_schema`)
    alt Output file exists AND overwrite=False
        Archiver->>TempStatsFile: Load existing stats file (sum, count) if updating
    end
    Archiver-->>You: Archiver object ready

    loop For each prediction batch
        You->>Archiver: archive(coord_dict, pred_dict)
        Archiver->>Archiver: Map predictions to output grid cells (`_flatten` / `_sample_sum_count`)
        Archiver->>Archiver: Calculate sum and count for each cell in this batch
        Archiver->>TempStatsFile: Update intermediate stats (sum, count) on disk (`_insert_output`)
        alt task_bytes limit reached
            Archiver->>TempStatsFile: Write accumulated stats from memory to disk
        end
    end

    You->>Archiver: Exit 'with' block (or error occurs)
    Archiver->>Archiver: Call close()
    Archiver->>TempStatsFile: Write any remaining stats from memory
    Archiver->>TempStatsFile: Load total sum and count from stats file
    Archiver->>Archiver: Calculate final average (sum / count)
    Archiver->>FinalOutputFile: Save final average to main output file (`_to_file`)
    alt keep_stats=False
        Archiver->>TempStatsFile: Remove stats file
    end
    Archiver-->>You: close() finishes
```
